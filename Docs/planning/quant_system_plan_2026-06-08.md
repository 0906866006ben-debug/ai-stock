## 0. 背景與定位（為什麼這份計畫長這樣）

這份研究報告是一座**特徵/假設的金礦**(多週期、量價四象限、均線扣抵、Wyckoff 相位、VCP、2B 假跌破、POC、三軸評分、台股微結構 gate),而且報告自己誠實標註:**A–T 已大致落地到 `backend/technical_analyzer/v1`,但 67 條假設全部 `not_tested`、正式回測執行器尚未完成。**

換句話說,系統現在的瓶頸**不是「缺特徵」,而是「缺驗證」**。

### 必須帶進這份計畫的 CANSLIM 慘痛教訓（用真錢前先記住）
前一套 CANSLIM 策略我們已用 15 年資料驗證,得到四個**會直接套用到這份報告**的結論:

| 教訓 | 數據 | 對本計畫的意義 |
|------|------|--------------|
| 技術/動能 edge 是**短線**的 | A 級 1m 中位 +0.34%、12m 反轉成 −8% | 設定 setup 時**先決定持有天期**,別把波段訊號拿來長抱 |
| **成本吃掉中位數** | 來回成本 NT$685 > A 級 1m 中位 NT$337 | 只做**預期波動 >> 成本**的 setup → 報告的 **3:1 RR 過濾**是對的 |
| **高分≠回撤小** | A 級最大回撤 −28% 比 D 級 −24% 還深 | 控制回撤靠**硬停損(風控層)**,不是靠分數 → 報告 v2.0 的 POC/MA60 硬停損是關鍵 |
| **訊號 edge ≠ 可投資組合** | 組合 CAGR 0.4% / maxDD −72% | **必須驗證權益曲線**,不能只看單筆統計 |

**結論:這份報告最有價值的不是它的技術指標(那些 CANSLIM 都有過、且證明很薄),而是它 v2.0 補上的「硬風控 + RR 過濾 + 執行紀律」——那正是 CANSLIM 死掉的那一層。**

## 1. 策略篩選（哪些值得用、哪些要降級）

以「可量化、可falsify、有獨立 edge 潛力、台股可執行」四個標準逐項判定:

| 模組 | 判定 | 理由 | 用法 |
|------|------|------|------|
| **2B 假跌破反轉**（v2.0 模組3） | ⭐ **優先驗證** | 定義精確(L1→L2 新低→3–5日收復)、有明確失效點、是「均值回歸」型而非追高 → 與動能策略不相關,可能是**真 edge** | 獨立 setup |
| **POC/MA60 硬停損 + 3:1 RR 過濾**（v2.0 模組4） | ⭐ **優先實作** | 直接解決 CANSLIM 的 −72% 與成本問題;客觀、可執行 | 風控層(所有 setup 共用) |
| **均線扣抵時間方框 + 臨界價**（v2.0 模組2） | ✅ **驗證** | 數學必然性、**領先**訊號、台股特色;但臨界價 ×1.01 是假設,需校準 | 時機因子 |
| **Volume Profile POC/VAH/VAL** | ✅ **驗證** | 客觀 S/R,給停損/目標一個非主觀錨點 | 停損/目標 + 結構 |
| **VCP / 多維有效突破**（3%+1.5×量+實體+籌碼） | ✅ **驗證(當波段 setup)** | CANSLIM 已知這是**短線**動能 edge → 必須配 RR+停損+短天期 | 波段 setup |
| **基本面硬過濾**（營收/EBIT/OCF/FCF/相對強度) | 🟡 **當 universe 過濾,不當報酬預測** | CANSLIM 證明基本面**品質加權**沒有前向報酬 edge;但「排除爛公司」仍合理 | 宇宙過濾(排除,非選股) |
| **台股微結構 gate**（處置/漲跌停/流動性/當沖) | ✅ **直接用** | 純衛生過濾,客觀正確,降低雜訊 | 硬過濾 + 信心上限 |
| **三軸評分 + 信心上限**（P/Q) | ✅ **保留** | 已實作、紀律好(mock/低流動性/單因子→降信心) | 框架 |

| **多週期 1:4:16 共振** | 🔻 **延後** | 自由度高→過擬合風險;且 15m/60m intraday 資料**尚未導入** | 待 intraday 資料 + 嚴格驗證 |

## 2. 嚴謹驗證原則（每個 Phase 都必須遵守）

### 2.1 Point-in-Time / 防偏誤（硬規範)
- **PIT**:財務用 `filing_date`、月營收用公布日、法人 T+1、技術指標用收盤後 → 訊號**隔日**生效。
- **含下市股**(survivorship-corrected):驗證任何「抗跌/反轉/恢復」一定要含下市/處置/終止交易標的。
- **還權價**:所有 MaxDD、停損、突破、扣抵一律用還權息價。
- **含成本**:來回 0.685%(手續費+證交稅)+ 滑價(依流動性分層,低流動性加大)+ 漲跌停無法成交處理。

### 2.2 統計嚴謹（避免「只比平均就自我感覺良好」)
- 報酬厚尾右偏 → 比**中位數**、用**無母數檢定**(Mann–Whitney);效果量(Cliff's δ)不只 p 值。
- 恢復速度 → **存活分析**(Kaplan–Meier + log-rank),未恢復當 censored。
- 分組差異 → **控制 size/beta/產業**(迴歸看增量係數),否則只是抓到「大型低 beta」。
- 事件少(崩盤 ~6 次) → **逐事件**列表 + permutation,不靠 pooled 灌顯著性。
- **預先寫死證偽條件**(decision gate),跑之前定好「達標才採用」。

### 2.3 反過擬合
- **凍結多數門檻在報告建議值,只開 3–5 個 `tunable`**;粗網格(3–5 步);walk-forward IS/OOS,WFE ≥ 0.5 才採用;±20% 參數敏感度;reward-hack guard(最少交易數、PF 上限、退化解剔除)。

### 2.4 分級制度（任何模組不得跳級)
**L0** 概念 / **L1** 資料研究 / **L2** 歷史回測(cohort) / **L3** paper trading / **L4** 小資金實測 / **L5** 正式自動化。

## 3. 分階段計畫（Phase 0–4）

> 原則:**先建驗證引擎,再驗證最可能有 edge 的「窄 setup」,再補風控與組合**。不重做 v1 已有的特徵,只補「驗證 + 風控 + 執行 + 組合」。

### Phase 0 — 驗證基礎建設（最優先,沒它後面全是空談）
**目標:** 把 CANSLIM 已有的 cohort / crash / walk-forward 回測骨架,改造成這套技術分析 hypothesis 的通用驗證執行器。
- **交付:**
  1. `hypothesis backtest executor`:讀 `hypothesis_backtest_v1.yaml` 的 67 條假設,逐條算「前向報酬 / 勝率 / 期望值 / MaxDD / RR 達成率」。
  2. **無交易模擬的 cohort 分析**(reuse CANSLIM `cohort_backtest.py`):每個 setup 觸發點往前看 1/5/20/60 日報酬 + 12 個月 max_dd_12m,分組對比。
  3. **含下市 + 還權 + 成本** 的資料層(canonical store 已在補齊)。
- **驗收:** 能對任一 setup 輸出「中位報酬、勝率、RR 分布、最大回撤、逐年/逐 regime 切面」。
- **Level:** 這是工具,不是策略。

### Phase 1 — Universe 過濾驗證（基本面 gate 到底有沒有用）
**目標:** 驗證 v2.0 基本面硬過濾(營收≥32億、成長15–20%、EBIT>0+產業z、OCF/FCF雙正、相對強度>大盤)**是否乾淨地排除輸家、而沒砍掉贏家**。
- **方法:** 通過 gate vs 未通過 gate 的前向報酬 + 下市率對比(含下市股、控 size/產業)。
- **decision gate:** 通過組的**下市率顯著較低、12M 報酬不顯著較差** → gate 當 universe 過濾保留;若把贏家也砍掉 → 放寬或降為加分。
- **Level:** L2。**先別假設基本面=好,先證明它至少「不傷害」。**

### Phase 2 — 高勝率 Setup 驗證（真正找 edge 的地方）
逐一驗證三個**最可能有獨立 edge** 的窄 setup,每個都用 Phase 0 引擎 + 含成本 + RR:
1. **2B 假跌破反轉**:極端偏離(BIAS120 < −40%)+ 新低誘空 + 3–5日收復 L1 + 扣抵翻轉 + 法人回補。
   - *測:* 收復後 1/3/6 月報酬、勝率、達 3:1 RR 比例、最大續跌(停損成本)。
2. **VCP / 多維突破**(短線波段):3% + 1.5×量 + 實體≥70% + 法人淨買 + POC 上緣。
   - *測:* 突破後 20 日報酬、假突破率、RR;**明確標為短天期**。
3. **均線扣抵加速**:扣抵走低區間 + 站穩臨界價 P_crit。
   - *測:* 臨界價 ×1.01 假設的校準 + 後續斜率翻轉的報酬。
- **decision gate(每個 setup):** 含成本後**中位 RR ≥ 某門檻、逐年/逐 regime 一致為正、樣本外不崩**。任一不過 → 該 setup 降級或淘汰。
- **Level:** L2 → 通過才到 L3。

### Phase 3 — 硬風控 + 執行模型（讓通過的 setup 變可交易）
**目標:** 把 v2.0 風控層落地並驗證它**真的把回撤壓下來而不殺掉報酬**。
- **交付:** POC −3% 硬停損、跌破下彎 MA60 趨勢停損、強制隔日離場、3:1 RR 過濾、ATR 1.5× 緩衝、「三有加一」結構。
- **驗證(無組合也能做):** 對 Phase 2 通過的 setup,加上停損後重算分布 → maxDD 應顯著下降、期望值不崩。
- **decision gate:** 風控使**MaxDD 明顯改善且 CAGR 犧牲可接受**(別像 CANSLIM 的 DD-breaker 把交易砍到剩 49 筆)。
- **Level:** L2/L3。

### Phase 4 — 組合建構 + Paper Trading（CANSLIM 死掉的那一層,務必做)
**目標:** 把「通過驗證的 setup + 風控」組成**可投資的權益曲線**。
- **交付:** top-K/週精選、單檔上限、產業上限、最大同時持股、Kelly(配最大曝險上限)、bear-year 降曝險。
- **驗證:** **組合 CAGR / MaxDD / Calmar / Sharpe**,逐年。對照 CANSLIM 的 0.4%/−72% 看有沒有真的改善。
- **decision gate:** Calmar、MaxDD、最差年虧損達門檻才進 paper;**paper 1–3 個月**確認執行可行,再談小資金(L4)。
- **Level:** L3 → L4。**不得跳過 paper 直接小資金。**

## 4. 各 Phase 驗收指標彙總

| Phase | 核心問題 | 過關條件 | Level |
|-------|---------|---------|-------|
| 0 驗證引擎 | 能不能誠實驗證任一假設? | 對 setup 輸出含成本的報酬/RR/MaxDD/切面 | 工具 |
| 1 基本面 gate | gate 有沒有傷到贏家? | 下市率↓ 且 12M 報酬不顯著↓ | L2 |
| 2 Setup edge | 2B/VCP/扣抵 有沒有含成本後的 edge? | 中位 RR 達標 + 逐年逐 regime 一致 + OOS 不崩 | L2→L3 |
| 3 硬風控 | 停損有沒有壓低回撤而不殺報酬? | MaxDD 明顯↓ + 交易數不被砍光 | L2/L3 |
| 4 組合 | 訊號變不變成可投資曲線? | Calmar/MaxDD/最差年達標 + paper 通過 | L3→L4 |

## 5. 風險與盲點（先講在前面)

1. **67 條假設全 not_tested** → 最大風險是「繼續加特徵而不驗證」。**Phase 0 不完成,其餘免談。**
2. **intraday(15m/60m)未導入** → 多週期共振、短線 setup 的真實性受限;先用日線可做的部分。
3. **籌碼/大戶/分點進階資料未完整接入** → 籌碼共振先用現有(法人/融資/PER),標降級。
4. **過擬合**:報告門檻多(32億、15–20%、3:1、POC 3%、BIAS −40%、2B 3–5日…)→ 全部當 hypothesis、凍結、敏感度測。
5. **2B / 抄底型策略的尾部風險**:接刀型 setup 若無嚴格停損,單次可能重傷 → 風控層必須先於 setup 上線。
6. **資料新鮮度**:目前 OHLCV/籌碼正在補齊(背景下載);驗證一定要用補齊後的 canonical store。

## 6. 下一步最小可行任務（MVT)

**MVT-1（純工具,可立即開始,零策略風險):**
把 CANSLIM 的 `cohort_backtest.py` / `crash_resilience.py` 改造成**通用 setup 驗證執行器**(Phase 0),先接一個最單純的 setup(例如「站上 MA20 帶量」)跑通,確認含成本/含下市/逐年切面都正確輸出。

**MVT-2(第一個真 setup 驗證):**
用 MVT-1 引擎驗證 **2B 假跌破反轉**(報告裡最像獨立 edge、最 falsifiable 的 setup)。結果二選一:
- 含成本後有穩定 RR → 你找到第一個值得做的策略,進 Phase 3 加風控。
- 沒有 → 乾淨淘汰,不浪費時間,換下一個 setup。

## 7. 一句話總結（交易員視角)

這份報告給了你**一座特徵金礦 + 一層 CANSLIM 當初缺的硬風控**。但它的 67 條假設**一條都還沒驗證**。所以正確的路不是「照單全收實作」,而是:**先建驗證引擎(Phase 0)→ 先證明基本面 gate 不傷人(Phase 1)→ 用含成本+RR 驗證 2B/VCP/扣抵這三個窄 setup(Phase 2)→ 補硬停損(Phase 3)→ 組成可投資曲線+paper(Phase 4)**。每一步都能 falsify、都標 Level、都先驗證再相信。

**別再重蹈 CANSLIM:做出漂亮的篩選器,卻沒有能賺錢的系統。這次先把「驗證 + 風控 + 組合」做對,特徵反而是最不缺的。**
