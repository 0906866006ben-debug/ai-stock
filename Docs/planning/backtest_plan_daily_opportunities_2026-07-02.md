# 每日交易機會——簡化回測計畫（2026-07-02）

目標：用本地既有資料驗證「每日交易機會」三桶分級規則（研究報告 v2 §5）是否具有
前瞻超額報酬。協定依報告 §6（簡化 forward-return 法），驗證通過的統計數字回填到
UI，取代「回測尚未完成」警告。

## 0. 資料現況（已盤點，全部在本地，無須新增爬取）

| 需求 | 來源（本地） | 覆蓋 |
|---|---|---|
| 日 OHLCV / 成交值 | `historical_data.db.ohlcv` | 2003-08 ~ 2026-06，2,517 檔 |
| 月營收 | `pit_fundamentals.db.month_revenue` | 2010-01 ~ 2026-06，2,428 檔 |

結論：**零資料採集工作**。唯一的資料任務是 Phase 1 的品質抽查與（可選）增量更新至今。

## 1. Phase 1 — 資料品質閘（半天）

1. 基準序列確認：0050 或加權指數在 ohlcv 的存在性與連續性。
2. 下市股覆蓋抽查：抽 10 檔已知下市股（如 2498 宏達電仍上市，找真下市案例）
   確認 ohlcv 是否含下市前資料 → 決定倖存者偏誤註記等級。
3. `month_revenue.date` 語義確認（該值為「營收所屬月」，非公告日）。
4. 各表 2010-2026 間的斷點/空洞掃描（每年 rows 數量曲線）。
5. （可選）`refresh_data.py` 增量補到最新交易日。

**通過標準**：基準可用、無系統性大空洞；下市覆蓋結論寫入報告註記。

## 2. Phase 2 — 訊號重建引擎（1-2 天）

逐交易日（2012-01 ~ 2026-06）重建三桶名單，規則與線上
`tw_daily_opportunities.py` 一致，但全部改讀 SQLite：

- **可買性**：收盤 ≥10、20 日均成交值 ≥3,000 萬（比線上版嚴謹：用均值非單日）、
  當日有 PER 資料；產業排除表後續接（Phase 1 若可從 FinMind info 快取取得產業）。
- **PIT 防線（報告 §6.2，不可省）**：
  - 月營收：所屬月 M 的數據於 **M+1 月 10 日**後才可見（保守法定期限）。
  - 法人買賣超：T 日盤後可見（T+1 起可用）→ 訊號日用截至 T 的 streak。
  - 進場價：訊號日 **次日開盤**；無次日開盤（停牌）→ 順延至下一有效開盤，超過
    5 個交易日剔除並計數。
- **分級**：與線上一致（S/A/B/C 門檻），同參數起點。
- **事件去重**：股票「新進入某等級」才算一個事件（前 20 個交易日內未曾在
  同級或更高級），避免同一持續狀態被重複計數。
- 產出：`backtest_signals_v2` 表（signal_date, stock_id, bucket, grade, metrics JSON）。

## 3. Phase 3 — 前瞻報酬計算（1 天）

- 視窗：T+5 / T+20 / T+60 / T+120 / T+250（長線桶另加 T+250）。
- 報酬：次日開盤進場，各視窗**收盤價**結算；來回成本 58.5 bps 一次性扣除。
  - 已知簡化：ohlcv 未還原除權息 → 報酬會**低估**（股息缺失），對「證明有 edge」
    是保守方向，可接受；註記之。
- 基準對照：同視窗 0050（或加權指數）報酬 → 超額報酬。
- 輸出矩陣：桶 × 等級 × 視窗 × 年度：
  - 事件數、平均/中位超額報酬、勝率（>基準比例）、P25/P75、最差年度。

## 4. Phase 4 — 判定與回填（半天 + 稽核）

**預先寫死的通過門檻（避免事後合理化）**：
- 中線桶 A 級以上：T+60 中位超額 > 0 且 ≥60% 年度為正，事件數 ≥ 150。
- 長線桶 A 級以上：T+120 或 T+250 中位超額 > 0 且 ≥60% 年度為正，事件數 ≥ 80。
- S 級應優於 A 級（單調性檢查）；若 B/C 與 A 無差異 → 門檻參數需檢討。

結果處理：
- 通過 → 統計數字寫入 `/tw/daily-opportunities` 回應 + UI 顯示
  「此等級歷史 T+60 中位超額 +X%（2012-2026，n=…）」，撤下未驗證警告、換成方法註記。
- 未通過 → 誠實保留警告，回報告調參（一次調整、重跑，禁止無限次挖掘）。
- **validation-auditor 稽核**（專案鐵則）：查 look-ahead / PIT / 倖存者 / 成本，
  任何 Critical → 結論作廢。

## 5. 已知限制（一開始就寫明）

1. 未還原除權息（報酬保守低估）。
2. 產業排除 / MAX / IVOL 濾網與線上 MVP 相同地未納入（第二輪再加）。
3. 倖存者偏誤程度取決於 Phase 1 抽查結果。
4. 簡化法不含滑價、部位管理、資金限制（報告 §6.3 全文照列）。

## 6. 時程與執行位置

- 全程在**本機**執行（資料庫在本地；雲端不參與）。
- 總工作量：約 3-4 個工作天等值；計算本身預估 <30 分鐘/全回測（pandas 向量化）。
- 順序：Phase 1 → 2 → 3 → 4，各 Phase 產出檢查點檔案，可中斷續跑。
